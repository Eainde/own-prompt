  <rule id="W1.R8" priority="CRITICAL" name="OWNERSHIP_DIRECTION_AND_NO_SUBSIDIARIES">
  STEP 1 — FIND THE TARGET AND READ THE ARROWS:
  Locate the target entity in the document's ownership chart. Do NOT assume "top = owner" or "bottom = subsidiary" — chart orientation varies. Instead, strictly FOLLOW THE ARROWS:
  - An arrow pointing FROM Entity A TO Entity B means "A owns B".
  - If an arrow points AWAY FROM the target entity towards another entity, it means the target entity OWNS that entity. That entity is a SUBSIDIARY and MUST BE EXCLUDED.
  - If an arrow points TOWARDS the target entity from another entity, it means that entity OWNS the target. That entity is an OWNER and should be included.
  - If the chart uses lines without explicit arrowheads, do NOT guess direction from percentage label position, vertical position, or visual proximity. Look for corroborating direction evidence elsewhere in the document (shareholder list, narrative text, corporate filings, certificate of incorporation, Form 20/40/41). If no corroborating evidence exists, mark the relationship direction as ambiguous, record in data_gaps, and DO NOT extract the relationship. NEVER infer direction from label placement alone.

  STEP 2 — CLASSIFY EVERY ENTITY AS OWNER OR SUBSIDIARY:
  Starting from the target entity, trace connections in BOTH directions and classify each entity:
  For each entity connected to the target (directly or via intermediaries), ask:
  "Does an arrow point from this entity towards the target (directly or indirectly)?" → OWNER → extract it
  "Does an arrow point from the target towards this entity (directly or indirectly)?" → SUBSIDIARY → SKIP entirely

  FOLLOW THE MONEY TEST: For each relationship, ask: "Who PAID money to acquire shares, and WHO ISSUED those shares?" The buyer/holder = owner. The issuer/company whose shares were acquired = owned.

  STEP 3 — EXTRACT UPWARD ONLY:
  Only extract the upward ownership chain — entities that directly or indirectly own the target.
  Do NOT extract entities that the target owns, controls, or has invested in.
  If a document shows both owners and subsidiaries of the target, ignore the subsidiaries entirely — no nodes, no edges.

  CRITICAL — MID-CHART TARGET:
  The target entity is often NOT at the bottom of the chart. It may sit in the MIDDLE with owners above AND subsidiaries below. You must ONLY go upward from the target.

  EDGE DIRECTION:
  owner = the entity holding the stake (higher layer). owned = the entity whose stake is held (lower layer).
  The target entity at layer 0 always appears in "owned" of its layer-1 edges, never in "owner".
  For each edge, record a direction_proof string that explains: why the owner entity holds shares in the owned entity (not the reverse), and the specific document page/section that proves this relationship direction.

  PER-EDGE VERIFICATION:
  Before finalizing each edge, ask yourself: "Does the document show an arrow from [owner] TO [owned]? Or does it show an arrow from [owned] TO [owner]?" If it's the latter, you have the direction backwards — swap them or remove the edge entirely if it points away from the target.
  </rule>

  <rule id="W1.R9" priority="CRITICAL" name="NO_PERSON_OWNS_PERSON">

  If a diagram shows multiple persons with percentages near each other, they are each shareholders of the same corporate entity — not owners of each other.
  VALIDATION: No edge may have both owner and owned resolve to nodes of type "Natural Person". If you produce such an edge, stop and re-examine: those persons each own shares in a common company.
  </rule>

  <rule id="W1.R10" priority="CRITICAL" name="BRANCH_ISOLATION">
  When the target entity has multiple direct owners (layer-1 entities), process each owner's shareholder branch independently:
  1. For each layer-1 owner, trace ONLY its shareholders upward. Do NOT mix shareholders between different layer-1 entities.
  2. LOOK FOR BRACKETS/LINES: In many charts, a group of shareholders is connected to a single company via a long vertical or horizontal bracket/line. This bracket acts as a strict boundary. You MUST assign all names connected to that specific bracket ONLY to the company that bracket points to.
  3. Do NOT cross bracket lines. If Person X is grouped under the bracket for Holding Co A, they MUST NOT be assigned to Holding Co B, even if their name is visually near it.
  4. If a person or entity holds shares in MULTIPLE layer-1 entities, create separate edges from that person/entity to each layer-1 entity. The person/entity appears as ONE node, but with edges to each holding it owns.
  5. DO NOT group or assign shareholders based on visual proximity, similar names, or shared family names. Just because names appear next to each other does NOT mean they belong to the same branch. Only use explicit lines, brackets, or table assignments.
  6. Before finalizing: for each layer-1 entity, verify that every shareholder (layer 2+) connected to it via edges actually owns shares in THAT specific entity — not a different one. Cross-check your branch assignments vigorously against the brackets.
  </rule>
