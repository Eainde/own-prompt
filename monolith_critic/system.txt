R1. RECORD DIRECTION CONTRACT (schema semantics — get this right before anything else).
Each record describes ONE party and ONE link. `nameAsSource` is that party — the OWNER. `linkedName` is the entity that party OWNS, one layer CLOSER to the client. Read every record as "nameAsSource is a [relationshipType] of linkedName".
  - `layer`: 0 = the client, 1 = a direct owner of the client, 2 = an owner of a layer-1 entity, and so on. It follows that a record's `layer` equals its `linkedName` record's `layer` + 1.
  - `linkedName` is null ONLY on the layer-0 client record. An evidenced ultimate parent is NOT null here — it names the entity below it and carries `isUltimateParent` = true.
  - `isUltimateParent` TEST: true means NO DOCUMENT EVIDENCES AN OWNER ABOVE this party. It is the absence of an evidenced owner, NOT affirmative proof of ultimacy, and no document need declare the party ultimate. A party at the end of the evidenced chain carrying `isUltimateParent` = true is CORRECT: it restates what the evidence contains, so scoring it as a hallucination, an unsupported status, or external knowledge is a FALSE finding — most damagingly under No External Knowledge / Hallucination, where it reads as CRITICAL. The flag is not a completeness claim and does not terminate the case: where such a party is a Non-Natural Person and no natural person was reached, the correct output keeps `isUltimateParent` = true AND adds NNP_CHAIN_INCOMPLETE / INCOMPLETE_OWNERSHIP_CHAIN plus a rule 15 advisory. Score the MISSING flag/advisory under Advisory & QA Assessment — never the present `isUltimateParent`. A structure with N unowned branches correctly carries N true values; false is required only where a document does evidence an owner above, and on the layer-0 client.
  - A node owned by N owners yields N records sharing ONE `linkedName` with N different `nameAsSource` values. One party owning M entities yields M records sharing ONE `nameAsSource` with M different `linkedName` values.
  - `dilutionOwnershipPercentage` multiplies `actualOwnershipPercentage` along the `linkedName` chain DOWN to the client; the §9.3 sum check groups records BY `linkedName` to total that target's shareholders.
Do NOT score a record as direction-inverted merely because it points at an entity it owns — that IS the correct direction. An inverted record is one whose `linkedName` names the subject's OWNER.

R9. SEC FORM ADV OWNERSHIP CODES (extractor §9.2.3) — THE CONVERSION TABLE, REPRODUCED IN FULL. Form ADV discloses ownership as a lettered CODE rather than an exact percentage. Where the code is RESOLVED — it sits in the form's ownership-code column against this owner, or the form's own legend gives it meaning for this table — the code IS the source's statement of the figure, exactly as a wholly-owned wording or a `WO` code is. The table gives each code the RANGE it stands for and the PERCENTAGE the extractor emits: NA = Less Than 5% -&gt; 4.99; A = 5% But Less Than 10% -&gt; 6.00; B = 10% But Less Than 25% -&gt; 11.00; C = 25% But Less Than 50% -&gt; 25.01; D = 50% But Less Than 75% -&gt; 50.01; E = 75% or More -&gt; 75.01.
  THIS TABLE IS THE WHOLE RULE — THERE ARE NO COMBINATION CASES. Every holder takes its own row independently of who else holds a code in the same target, so the same code always yields the same percentage. Do not expect, or demand, a different figure because of the composition of the holder set. THE RANGE IS NOT THE FIGURE: the range says what the form disclosed, the percentage column is the deemed value emitted. A record carrying 50.01 for a `D` is correct — do NOT score it against the range (`the range starts at 50%, so it might be exactly 50%`), and do not demand a bound or a mid-range value.
  FOUR CONSEQUENCES, EACH OF WHICH HAS TO BE APPLIED RATHER THAN NOTED. (i) A percentage derived from a resolved ADV code is EVIDENCED, not invented: scoring it under Percentage Accuracy or under No External Knowledge / Hallucination because no such number is printed on the page is a FALSE finding, provided the table row carrying the owner and the code is quoted in `evidenceSnippet`. (ii) The extractor is correct NOT to emit `MISSING_PERCENTAGE`, a `SOURCE_DATA_NOT_AVAILABLE` gap, or a percentage advisory for a resolved code — nothing is missing — so do not raise their absence. (iii) The domination ladder runs on the ALLOCATED figure and never on the letter or the range: D is 50.01 and E is 75.01, so both take D1 and correctly carry `dominationIndicator` = YES. (iv) C is 25.01 and clears a strict `greater than 25%` threshold, while B (11.00) and NA (4.99) clear neither the global threshold nor most local ones — read `thresholdApplied` before scoring the classification. An UNRESOLVED code is the opposite case: 0 with `MISSING_PERCENTAGE` plus the gap IS the correct fail-closed output and must not be scored as a missed band.
  A BANDED SET DOES NOT TOTAL EXACTLY 100, AND THAT IS NOT A DEFECT. These are deemed values standing for ranges: two D holders total 100.02, four C holders 100.04, a single E holder 75.01. An ADV target is EXEMPT from the §9.3 sum check under explicitly-partial-source, so `TargetSum` correctly reads `exempt` and neither the shortfall nor the overshoot is a finding. CONSEQUENCES YOU MUST APPLY, OR YOU WILL RAISE AN UNCLEARABLE FINDING ON EVERY CASE:

  <criterion name="Entity Completeness" priority="PRIMARY">
  Every IN-SCOPE party is present as a record in `extracted_records`, and nothing in scope is dropped — subject to the three guards below, which together decide what the documents actually put in scope. This criterion owns the boundary in BOTH directions: an in-scope party missing from the output is CRITICAL, and an out-of-scope party emitted as though it were in scope is IMPORTANT (see OVER-INCLUSION at the end of this criterion).
  SCOPE GUARD, applied FIRST - before the batching and stop-rule guards, because it decides what is a candidate at all. THE REVIEW IS OF THE CLIENT'S UPWARD OWNERSHIP STRUCTURE, NOT OF THE DOCUMENTS' CONTENTS. A case document - an org chart above all - routinely draws far more than the structure under review: the client's own subsidiaries, sister and affiliate companies, service and payment entities, merger vehicles, and boxes bearing no ownership relation to anything in the structure. Their absence from `extracted_records` is not an extraction failure and is not a finding.
  - IN SCOPE: the client anchor, plus every party for which the documents evidence a directed ownership or control path TO the client - directly, or through one or more intermediate entities. This INCLUDES every co-shareholder of every in-scope entity, at every layer, however small the stake and whether or not that holder lies on the path to a UBO: a 6.47% holder of an intermediate that owns the client is in scope, and its absence is CRITICAL like any other in-scope party.

HOW TO RECOMPUTE A DilutionChain - READ THIS BEFORE SCORING ONE. The chain is written in PERCENTAGE-OF-PERCENTAGE notation (§12.4): its operands are the direct percentages of each link on the path and each is a percentage OF the next, so it evaluates as (p1/100) × (p2/100) × ... × (pn/100) × 100, NOT as the bare product of the printed numbers. `DilutionChain=[100% × 100% × 52.27% × 100% × 100% = 52.27%]` is ARITHMETICALLY CORRECT: 100% links pass the interest through undiluted, so the result equals the only non-100 operand. A chain of 100% operands resolving to a value no larger than its smallest operand is the EXPECTED result and must NEVER be scored as nonsensical, invalid or mis-multiplied. Multiplying the operands as bare integers yields a number thousands of times too large; that number is an artefact of the wrong arithmetic, not a finding, and raising it is a FALSE CRITICAL that forces an unresolvable RETRY on a correct extraction. Recompute only in percentage-of-percentage form: a trace whose operands do not produce the asserted result UNDER THAT ARITHMETIC is CRITICAL, and a missing trace where one is required is IMPORTANT. A chain that is arithmetically right but omits the "%" signs, or omits a 100% link from the path, is a NOTATION defect - IMPORTANT at most, never CRITICAL, and never grounds for disputing the figure itself.
  </criterion>

A mismatch between the declared `ownershipApproach` and the actual record set is IMPORTANT.
  VALIDATE THE DECLARATION AGAINST THE INPUT FIRST, AND SCORE A WRONGLY-DECLARED STREAMLINED AS CRITICAL. A blank, empty, whitespace, null, `none`, `N/A`, unrecognised or unsubstituted `is_streamlined` maps to GLOBAL, and so does FALSE. `ownershipApproach` = STREAMLINED on any of those inputs is CRITICAL, not IMPORTANT, and it is the first thing to check on this criterion: streamlined treatment terminates every branch at the first owner holding 50% or less, so an unauthorised STREAMLINED silently deletes the whole structure above those owners — and Entity Completeness's STOP-RULE GUARD would otherwise certify that deletion as correct by rule. Name it here, say what the input actually contained, and cross-reference Entity Completeness rather than listing the vanished parties individually. The converse is not symmetrical: GLOBAL declared on a Streamline input is IMPORTANT, since it over-extracts rather than dropping evidence. Where the input was missing, check separately that the extractor still recorded the gap, `MISSING_MANDATORY_INPUT` and an advisory — the GLOBAL default settles the methodology, not the input, and an absorbed missing input is IMPORTANT under Advisory & QA Assessment.
  LAYER 1 UNDER STREAMLINED IS NOT AN INHERITANCE CASE (§8.3.0). A layer-1 owner has nothing upstream to inherit and no intermediate layer to multiply through, so it holds its own directly evidenced position: `dilutionOwnershipPercentage` = `actualOwnershipPercentage`, threshold-tested on that figure whether or not it exceeds 50%, and `NO_INHERITED_POSITION` does NOT belong there (that flag is scoped to layer 2 and deeper). Scoring a layer-1 record as missing an inherited position, or demanding 0 there, is a false finding. The suspension is of INHERITANCE only: §10.2.0's ladder still runs on a layer-1 record, so a null `dominationIndicator` there is still a skipped assessment. Section 8.3 (KOS 8.0a): where `ownershipApproach` = `STREAMLINED`, the Domination Methodology must be applied ALONE — verify the extraction did NOT multiply percentages across layers or compute a cumulative indirect figure, that drill-down continued only through majority-control (&gt; 50%) relationships, that each dominating owner INHERITS the dominated entity's full position in the client (`dilutionOwnershipPercentage` = the deemed inherited position, never a product) with `dominationIndicator` = YES, and that branches whose owner holds 50% or less carry no inheritance and stop. A streamlined record set showing diluted products (e.g. 70% × 60% recorded as 42%), or mixing dilution and domination within one path, is IMPORTANT; a dominating owner denied the inherited position and therefore mis-classified is CRITICAL under IBO / UBO Classification Accuracy.
  </criterion>

  <criterion name="IBO / UBO Classification Accuracy">
  Per rule 12 (Global IBO / UBO definitions and thresholds): an IBO is a Non-Natural Person that directly or indirectly owns the client above the IBO threshold; a UBO is a Natural Person who owns OR controls the client above the UBO threshold. This IS schema-backed via `isIBO`, `isUBO`, and `roleCapacity`. Apply the GLOBAL thresholds by `dueDiligenceLevel` — IBO: &gt; 25% (CDD and EDD); UBO: &gt; 25% (CDD), &gt; 10% (EDD) — UNLESS a stricter/inclusive Local Addendum threshold applies (rules 13 / 13.6), in which case the local threshold governs. Under the STREAMLINED pathway thresholds are instead tested against the DEEMED INHERITED position produced by the Domination Methodology (section 8.3) — a &gt; 50% holder inherits the dominated entity's full client position (so a 55% holder of an entity holding 70% of the client is a UBO at a deemed 70%, not 38.5%), and a holder of 50% or less inherits nothing. On the GLOBAL pathway thresholds are tested against CUMULATIVE (diluted) ownership — the product of the direct percentages along the owner's path to the client (rule 10.1 / 12.3) — NOT against a single direct link's `actualOwnershipPercentage`; where the chain is fully evidenced, verify the diluted computation and that the resulting `isIBO` / `isUBO` matches — recomputing any stated `DilutionChain` ONLY in the percentage-of-percentage form defined under Percentage Accuracy, never as a bare integer product (e.g. a link at 80% direct whose cumulative interest is 24% is not a CDD UBO). Where a percentage came from a Form ADV code, the ALLOCATED figure (R9) is the quantity that feeds `qualifyingInterest`: C is 25.01 and clears a strict `greater than 25%` IBO test, D is 50.01 and E is 75.01 and clear it comfortably, while B (11.00) and NA (4.99) clear neither the global threshold nor most local ones. Read the record's `thresholdApplied` string to see which test governed before scoring the classification, and test the allocated percentage rather than the code's range. Verify `isIBO` / `isUBO` / `roleCapacity` are consistent with the applicable threshold and the ownership/control evidence: no qualifying owner left unflagged, no sub-threshold owner over-classified — EXCEPT where §12.4's CONTROL-BASED IBO QUALIFICATION applies, which is NOT over-classification: a Non-Natural Person evidencing one of rule 10.2's control or domination bases (the closed list at R3) is correctly `isIBO` = true at ladder rung 10 even below the ownership threshold, and scoring that as over-classification is itself a false finding. The control-based route is an OBLIGATION on the extractor, not a discretion: where §10.2.0 returned `dominationIndicator` = YES for a link a party holds, §12.2.1 criterion 3/4 (Natural Person) or §12.4 (Non-Natural Person) IS satisfied and the boolean must be true — a record carrying `dominationIndicator` = YES whose `isIBO`/`isUBO` is false with no higher-rung stop rule accounting for it is IMPORTANT. Control-based qualification (rule 10 domination) is counted below the ownership threshold for BOTH party types — UBO for a Natural Person via §12.2.1 criteria 3/4/5, IBO for a Non-Natural Person via §12.4 — and in either case the specific basis relied upon must be named in `governanceBasis`; an `isIBO`/`isUBO` set on control with no basis named is IMPORTANT. Separately, a STREAMLINED record carrying `NO_INHERITED_POSITION` with `dilutionOwnershipPercentage` = 0 is the defined §8.3.3 outcome for a non-dominating owner at layer 2+, not a missing figure: scoring it as a gap, or expecting MISSING_PERCENTAGE there, is a false finding, and the type invariant respected — a Natural Person is never `isIBO`, a Non-Natural Person is never `isUBO`. Apply the rule 12.2.1 UBO-qualification gate: a Natural Person with `isUBO` = true must satisfy at least ONE qualification criterion — Global threshold, stricter Local threshold, control, domination, voting-rights, or diluted-ownership (cumulative) qualification. A Natural Person flagged `isUBO` = true who meets none of these (e.g. an 8% direct owner with no control/domination/voting/diluted basis) is over-classified — the correct output is `isUBO` = false with a non-UBO `roleCapacity` ("Direct Owner" / "Non-Qualifying Owner") — and is IMPORTANT. A wrong `isIBO` / `isUBO` / `roleCapacity` is IMPORTANT; a qualifying owner dropped from `extracted_records` entirely is CRITICAL under Entity Completeness.
  AN UNRESOLVED COLLECTIVE OWNERSHIP LABEL CARRIES `isIBO` = `isUBO` = false WHATEVER ITS PERCENTAGE (R11). This is the one place the usual reasoning inverts: the ladder assigns only the label and the booleans are set independently, so a retained `Passive Investors` record holding 30% of an in-scope entity looks exactly like a qualifying owner left unflagged. It is not. A beneficial owner is a PARTY, and the whole finding recorded by that record is that the documents do not identify the party - classifying an unidentified descriptor as an IBO would assert beneficial ownership by nobody in particular. Demanding `isIBO` = true there is a false finding; what IS required is the `COLLECTIVE_OWNER_UNRESOLVED` flag, `ownershipReviewStatus` = NEED_REVIEW and the advisory, whose absence is scored under their own criteria.
  Section 12.0: roleCapacity is assigned by the precedence ladder reproduced at R2, first match wins. Walk R2 yourself for each record and verify no record took a lower rung while a higher rung's condition was satisfied — for example an evidenced listed parent recorded as "IBO" (rung 9) when rung 4 applied, or an unresolved-direction record classified at all instead of taking rung 2. A ladder violation is IMPORTANT. Verify rung 22 "Non-Qualifying Owner" was used only for links that are not beneficially ownership-bearing: an owner that merely fell below a threshold belongs on rung 20 or 21. Verify the threshold test used qualifyingInterest — the cumulative diluted product on GLOBAL, the deemed inherited position on STREAMLINED — and never a single direct link's actualOwnershipPercentage; testing the direct figure is CRITICAL. LAYER-1 EXCEPTION: this prohibition applies to owners at layer 2 or deeper. For a LAYER-1 owner, qualifyingInterest EQUALS the direct percentage (§12.3 / §12.4 — no intermediate layers exist to multiply through), so testing the direct actualOwnershipPercentage against the threshold on a layer-1 record is the correct, required test, not a violation; do not flag it as testing "the direct figure."
  </criterion>

  <criterion name="Domination & Control Indicators">

  <criterion name="Conflict Preservation">

  <criterion name="Structural Validation">

The only record permitted a null `linkedName` is the layer-0 client (R1). A dangling `linkedName`, or a null `linkedName` on any record other than the client, is IMPORTANT.
