<section name="ENTITY_NORMALIZATION_PIPELINE">
Apply to all non-Natural-Person node types: Listed Company, Private Company, Regulated Entity, SPV, Trust, Charity, Foundation, Partnership, Government Entity, Branch, Unknown.

Step 1 — LEGAL SUFFIX STANDARDIZATION:
Identify and standardize the legal suffix in the name. The suffix is preserved in `normalizedName` in its canonical form.

Recognized legal suffixes (case-insensitive):
  German:    AG, GmbH, KG, KGaA, OHG, GbR, SE, eG
  UK/Irish:  Ltd, PLC, LLP, CIC
  US:        Inc., LLC, LP, LLP, Corp., Co.
  French:    S.A., S.A.R.L., S.A.S., S.C.A.
  Dutch:     B.V., N.V., C.V.
  Swiss:     AG (same as German), Sàrl
  Italian:   S.p.A., S.r.l., S.n.c., S.a.s.
  Spanish:   S.A., S.L., S.L.U., S.C.
  Nordic:    AB (Swedish), AS (Norwegian/Danish), Oy (Finnish), A/S (Danish)
  Other:     S.A. de C.V. (Mexican), Pte. Ltd. (Singapore), Bhd. (Malaysian)

If the suffix is present but uses a variant spelling (e.g. "Gmbh" → "GmbH"), standardize to the canonical form in `normalizedName`. Note in `normalizationNote`.

Step 2 — NORMALIZEDNAME:
Set `normalizedName` to the name with the standardized suffix. Preserve all diacritics. Apply title case only if the name is in ALL CAPS (likely OCR artifact).

Step 3 — DEDUPKEY GENERATION:
  a. Start with the `normalizedName` (not `name`)
  b. Strip the legal suffix (do not include it in the key)
  c. Lowercase the remaining string
  d. Replace all spaces, hyphens, and punctuation with underscores
  e. Collapse consecutive underscores to one
  f. Strip leading and trailing underscores
  Example: "Deutsche Bank AG" → strip "AG" → "Deutsche Bank" → lowercase → "deutsche bank" → underscores → "deutsche_bank"
  Example: "HSBC Holdings PLC" → strip "PLC" → "HSBC Holdings" → "hsbc_holdings"
  Example: "Société Générale S.A." → strip "S.A." → "Société Générale" → "société_générale"

Step 4 — ASCIIDEDUPKEY GENERATION:
  Apply diacritic-to-ASCII mapping to `dedupKey`:
  ü → ue, ö → oe, ä → ae (German umlauts — digraphs, not strip)
  ß → ss
  ő → oe, ű → ue (Hungarian)
  é, è, ê, ë → e
  á, à, â, ã → a
  í, ì, î, ï → i
  ó, ò, ô, õ → o
  ú, ù, û → u
  ñ → n, ç → c, ø → o, å → a, ð → d, þ → th, ł → l
  ś, š → s, ź, ž → z, ć, č → c, ř → r
  For any diacritic not listed, strip to the closest base Latin character.
  Example: "société_générale" → "societe_generale"
  Example: "müller_ag" → "mueller_ag" (ü → ue digraph)

Step 5 — SET PERSON FIELDS TO NULL:
  Set firstName, middleName, lastName, personalTitle to null for all entity nodes.
</section>

<section name="PERSON_NORMALIZATION_PIPELINE">
Apply to nodes where type = "Natural Person". Apply steps in this exact order.

Step 1 — SCRIPT CONVERSION (L1):
Convert non-Latin scripts to Latin using the appropriate romanization standard:
  Chinese (汉字): Official Pinyin romanization — 王明华 → Wáng Mínghuá
  Japanese (漢字/カタカナ): Modified Hepburn romanization
  Korean (한글): Revised Romanization
  Arabic (العربية): ISO 233-compatible transliteration
  Cyrillic: ISO 9 transliteration
If already Latin script, skip. Note conversions in `normalizationNote`.

Step 2 — HONORIFIC AND SUFFIX STRIPPING (L7):
Strip honorifics → place in `personalTitle`:
  Dr., Dr → "Dr." | Prof., Professor → "Prof." | Herr → "Herr" | Frau → "Frau"
  Mr. → "Mr." | Mrs. → "Mrs." | Ms. → "Ms." | Miss → "Miss"
  Sir → "Sir" | Dame → "Dame" | Lord → "Lord"

Strip name suffixes and DISCARD (do NOT place in personalTitle or any name field):
  Jr., Jr, Junior | Sr., Sr, Senior | I, II, III, IV, V (generational)
  Esq., CPA, MBA, PhD (professional credentials)
  Note each in `normalizationNote`: e.g. "Name suffix 'Jr.' stripped."

Step 3 — NAME PARSING (L3):
Split the remaining name into firstName, middleName (nullable), lastName:
  Western order (given + family): first=given, middle=middle, last=family
  Eastern order (family + given): detect by script/context — first=given, last=family
  Mononym (single name): firstName=null, lastName=name
  Hyphenated first name: keep hyphen as single firstName ("Hans-Peter")

Step 4 — COMMA-ORDER REPAIR (L4M):
If the name (after honorific stripping) matches pattern "Word, Word [Word...]":
  "Smith, John" → firstName="John", lastName="Smith"
  "Smith, John Robert" → firstName="John", middleName="Robert", lastName="Smith"
  Note in `normalizationNote`: "Comma-order repair applied."
  Guard: if firstName == lastName after repair, investigate — do not blindly swap.

Step 5 — COMPOUND SURNAMES (L8):
  Particles (van, von, de, di, la, el, al): include in lastName — "Von Beethoven"
  Hyphenated surnames: keep hyphen — "García-López"
  Double surnames (Hispanic, no hyphen): keep both — "García López"

Step 6 — TITLE CASE (L4):
  Apply Title Case to firstName, middleName, lastName.
  Preserve hyphens: "HANS-PETER" → "Hans-Peter"
  Preserve common patterns: "McDonald" not "Mcdonald"

Step 7 — DIACRITICS (L2):
  Preserve diacritics in all name fields. "Müller" stays "Müller". Do NOT strip.
  Diacritic stripping occurs only in `asciiDedupKey`.

Step 8 — OCR HEALING (L5):
  Fix obvious OCR errors only when cross-referencing confirms the correction.
  "Müiler" → "Müller" (if "Müller" appears elsewhere). Note in `normalizationNote`.
  If uncertain, do NOT heal.

Step 9 — ALIAS DETECTION (L6):
  If another node shares the same lastName and firstName initial, flag as possible alias.
  Note in `normalizationNote`: "Possible alias: see also '[name]' (id: [id])"
  Do NOT merge.

Step 10 — DIMINUTIVE ALIASING (L6B):
  Detect recognized diminutive first names. Flag the formal equivalent in `normalizationNote`.
  Do NOT change firstName.
  English: Bill/Billy→William, Bob→Robert, Jim→James, Joe→Joseph, Mike→Michael,
    Tom→Thomas, Dan→Daniel, Pete→Peter, Ben→Benjamin, Sam→Samuel,
    Rick/Dick→Richard, Liz/Beth/Betty→Elizabeth, Nick→Nicholas, Ted→Theodore
  German: Willi→Wilhelm, Uli→Ulrich, Heinz→Heinrich, Hans→Johann/Johannes,
    Sepp→Josef, Fritz→Friedrich
  Slavic: Oleksandr→Alexander, Dmytro→Dmitry, Mykola→Nikolai/Nicholas

Step 11 — DEDUPKEY GENERATION (L9):
  dedupKey: lowercase(firstName) + "|" + lowercase(lastName)
  Mononyms (firstName=null): "|" + lowercase(lastName)
  Example: firstName="Hans-Peter", lastName="García López" → "hans-peter|garcía lópez"

Step 12 — ASCIIDEDUPKEY GENERATION:
  Apply the same diacritic-to-ASCII mapping as in entity normalization to `dedupKey`.
  Example: "hans-peter|garcía lópez" → "hans-peter|garcia lopez"
  Example: "münchen|müller" → "muenchen|mueller" (ü → ue digraph)

Step 13 — NORMALIZEDNAME FOR PERSONS:
  Set `normalizedName` to the full name in Title Case without honorific:
  firstName + " " + (middleName + " " if present) + lastName
  Example: firstName="Hans-Peter", lastName="García López" → "Hans-Peter García López"
</section>
