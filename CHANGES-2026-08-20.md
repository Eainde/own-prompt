## 1. Policy rules added from the source documents

These implement instruction text supplied today (V41 and the KOS 8.0a extract). No interpretation beyond what the source states.

**§8.3 — Streamlined means Domination Methodology ONLY** (KOS 8.0a / DBLM)
When `isStreamlined = TRUE`: never multiply percentages across layers, never compute a cumulative indirect figure, drill down only through majority-control (>50%) relationships. A >50% holder **inherits the dominated entity's full position** in the client — 55% of an entity holding 70% of the client makes you a UBO at a deemed **70%**, not 38.5%. A holder of ≤50% inherits nothing and that branch stops. Includes the full ABC/JKL/GHI/DEF worked example and its outcome table.

**§9.2 — Wholly-owned wordings ARE percentage evidence**
"wholly owned subsidiary of", "sole member", "single shareholder", "sole shareholder", "entirely owned by", "fully owned and controlled by" each mean exactly **100%**. Assign `actualOwnershipPercentage = 100` and quote the wording — do **not** emit 0 + `MISSING_PERCENTAGE` because no number is printed.

**Rule 6 — ORBIS "MO" is not a percentage**
"MO" / "Majority Owned" / "Majority Control" / "Majority-Owned Subsidiary" / "Majority Shareholder" with no stated figure evidences only **>50%**. Never infer 51%, never upgrade to 100%. Emit 0 + `MISSING_PERCENTAGE` + `SOURCE_DATA_NOT_AVAILABLE`, flag `ORBIS_MO_PERCENTAGE_NOT_DISCLOSED`, raise an advisory for the exact figure.

**§9.1 check 2 — "Total Ownership" is indirect**
Any percentage under a "Total Ownership" heading is an aggregate held through intermediates. Report as indirect only; never record it as a direct link percentage.

> **Collision resolved:** §9.2 says "read the wording as 100%" while ORBIS MO says "never infer a percentage". Left alone, a model would have upgraded "majority-owned subsidiary" to 100%. Both rules now carry an explicit cross-reference forbidding that.

## 2. Determinism rules — the response to the inconsistency report

Each targets a specific reported drift category.

**§9.0 — Entity inventory before links** *(targets: which parties get found)*
Extraction is now two-pass. Enumerate every party in every document **first**, then build links only between inventoried parties. A party absent from the inventory must not appear in output; an inventoried party with no link is recorded as a `qaFlags.records` entry with status `NEED_REVIEW`. Makes the inventory a closed set the output is reconciled against.

**§9.3 — Per-target sum check** *(targets: which parties get found)*
For each owned entity, its shareholders' direct percentages should total ≈100% (±5%), **counting each distinct holder once**. Below 95% → re-scan, then `INCOMPLETE_SHAREHOLDER_SET` plus a data gap — never an invented shareholder. Above 105% → `OWNERSHIP_PERCENTAGE_CONFLICT`. Exempt: unknown percentages, and sources that *positively state* they are partial (silence is not an exemption).

This is **the only mechanism in the entire prompt that lets a run detect its own omission.** A 70% sum is positive evidence a shareholder was missed.

**§12.0 — `roleCapacity` precedence ladder** *(targets: classification calls)*
Rule 12 previously said only "determine using evidence and applicable rules" across 22 values, with two escape-hatch phrases and no tie-break — so the same facts could yield different classifications on different runs. Now a **22-rung ladder, first match wins**, no weighing and no skipping. Ownership precedes control for both party types.

**§12.4 — Arithmetic and rounding contract** *(targets: the numbers)*
Thresholds test `qualifyingInterest` — the cumulative diluted product on GLOBAL, the deemed inherited position on STREAMLINED — never a single direct link (except a layer-1 owner, where they are the same figure). **Compare unrounded, report rounded** half-up to 2dp, never round intermediates. Rounding before comparing would let 24.996 become 25.00 and flip an inclusive ≥25% test.

Operands must be written **before** the result: `DilutionChain=[80 × 60 × 50 = 24.00]`. In rule 18's reasoning line the trace tokens now precede `Classification`/`Conclusion`, so a verdict can no longer be asserted first and the arithmetic backfilled to match.

**Canonical record order** *(targets: narrative/ordering)*
`id` was "document reading order" — undefined, because the prompt receives *multiple* documents, so two substantively identical runs diffed on every line. Replaced with a **total sort**: layer → linkedName → nameAsSource → relationshipType → documentName → pageNumber, with NFC-normalised, case-folded collation and a final tie-break on canonical JSON so ordering is never ambiguous.

⚠️ **Visible change:** records no longer appear in document order. Anything rendering by `id` will look reshuffled to reviewers.

**No assertion without a quote** *(targets: hallucinated parties)*
Any record asserting a non-zero percentage or a `linkedName` requires a non-null verbatim `evidenceSnippet` and a numeric `pageNumber`. Null is permitted only when **all three** hold: `linkedName` is also null, no percentage is asserted, and a gap flag is carried. *A party that cannot be quoted must not be asserted.*

## 3. Conflicts found and resolved

A whole-prompt review read all rules together as one system — something no incremental review had done.

### Critical

**ORGCHART contradicted §9.1 and KERNEL C.** For an ambiguous chart, ORGCHART said *"treat the entity directly above as the presumed direct shareholder"* (guess); §9.1 check 5 said direction can't be taken from chart position and to flag `OWNERSHIP_DIRECTION_REVIEW_REQUIRED` (fail closed); KERNEL C bars inferring relationship paths and is marked non-negotiable. Three rules, three answers, all CRITICAL.
→ The upward reading is now a **hypothesis, never evidence**. Unconfirmed, §9.1 governs and ORGCHART yields.

**§12.4 contradicted its own worked example — AML-material.** A drafting error set `isIBO = false` for *any* streamlined owner at ≤50%, which would have suppressed IBO/UBO flags for ordinary direct owners. §8.3.2's own example concludes **"DEF Ltd = IBO (30% of Client)"**.
→ Root cause: §8.3.3's *"carries only its own position and inherits nothing"* means *has its own position, doesn't inherit an upstream one*. Now scoped to layer 2+, with the evidence-based qualification routes preserved.

**Unlinked parties were routed to a container that cannot hold them.** §9.0 sent them to `outOfBounds`, whose `records` entries **require an integer `id`** referencing a record the party is explicitly forbidden from having.
→ Re-routed to `qaFlags.records`, which requires only `{reason, status}`.

### Important

**The prompt named ~30 fields that don't exist in the schema** — `dataGaps`, `advisorySummary`, `classificationStatus`, `documentConflicts`, `stopRuleApplied`, `confidenceStatus` — with no indication which were real. Rule 1 alone mandates capturing 15 document attributes, **13 of which have no output home**.
→ New **`FIELD-VOCABULARY`** rule (CRITICAL, placed before rules 1 and 9) maps every working name to its schema destination or explicitly to *"working state, never emitted"*.

**Direction-inversion hazard in the prompt's own vocabulary.** Rule 9 lists `ownerName` first and `ownedEntityName` second; the emitted record is the reverse — `nameAsSource` is the **owned** subject, `linkedName` points at its **owner**. Mapping them positionally inverts every ownership edge — the exact defect ORGCHART and §9.1 both exist to prevent.
→ Called out explicitly in `FIELD-VOCABULARY` and cross-referenced from rule 9.

**Others corrected:** §9.3 double-counted rule 14's retained conflicting versions (spurious >105%); rule 18's `Classification` offered a 6-value vocabulary against a 22-value enum, including `Control-Based UBO` — wrong for an entity; `PROCESSING-ORDER` diverges from rule numbering after step 13 (step 13 = rule 14), and rules 13 and 18 are not steps at all; ladder rung 10 had no defined firing condition for entities; the streamlined ≤50% case had no defined emission.

## 4. Critic prompt

Every extractor rule needs a matching critic check, or it is a rule nobody polices. Five criteria extended: **Entity Completeness**, **Percentage Accuracy**, **IBO/UBO Classification Accuracy**, **Conflict Preservation**, **Structural Validation**.

One defect worth naming: the critic **contradicted itself** on `evidenceSnippet` — one criterion carried the old rule, another the new — so its verdict flipped between RETRY and ACCEPT_WITH_NOTES depending on which it weighed. The critic's own output was run-to-run unstable, inside a project about run-to-run stability. Resolved.

## 5. How this was verified

- **82 automated tests**, up from 25. Roughly 30 exist because a specific defect got past a review.
- **Every regression test was demonstrated failing** against the pre-fix prompt before being accepted, then passing, with byte-identical restores. This became policy after two earlier tests were found to be vacuous — one named `..._before_the_result` that checked no ordering, and one that passed unconditionally against a pre-existing enum value.
- Tests that read the **schema directly**, so a schema change breaking a rule fails the suite: every `FIELD-VOCABULARY` mapping resolves to a real field; the 22 ladder rungs match the enum exactly; `qaFlags.records` does not require an `id`.
- A **cross-check test** binds the prompt's stated record ordering to the harness implementation, so the two cannot silently diverge.

## 6. Needs a decision — three policy questions

**These are AML policy semantics currently hard-coded into a production prompt on a reading of intent, not on stated source text.** None blocks the code landing; all three should be confirmed by the KOS text owner before deployment.

**1. `Direct Owner` vs `Non-Qualifying Owner`.** The source names both enum values for a single decision. Implemented as: `Direct`/`Indirect Owner` (rungs 20/21) are threshold failures; `Non-Qualifying Owner` (rung 22) is reserved for links not beneficially ownership-bearing, e.g. an evidenced nominee holding. **If they are meant as synonyms, one value should stop being used.**

**2. The ±5% completeness band (§9.3).** Assumes sources intend to list all shareholders. Guarded by "purports to list the complete set" plus exemptions, but **if real caseloads are mostly partial extracts this will be noisy** and should become opt-in.

**3. Notional UBO.** §11.1.1 states flatly *"DO NOT classify the individual as Notional UBO"* and directs a QA flag instead. The affirmative classification is now reachable **only** where a Local Addendum expressly requires it, via rule 7's local-override principle plus §13.4's jurisdiction list. **This is a reading, not a stated rule.**

## 7. Not done

- **`temperature = 0` has not been set.** This is the cheapest available lever and is expected to absorb a large share of the variance. It is a sampling setting, not a prompt change.
- **No baseline measurement exists.** To prove any of this worked, capture 5 runs of one case from the **pre-change** prompt (recoverable from git) and 5 from the current one, then compare. A harness for exactly this is in `tests/consistency.py`.
- **The test suite is not in version control.** `.gitignore` excludes `tests/` repo-wide, so committing the 82 tests requires `git add -f`.

**Honest assessment of expected gain:** ordering and classification drift should be largely resolved. Party-set drift partly — §9.0 leaves no artefact in the output, so a skipped inventory pass is undetectable. Numeric drift least: the model still performs the arithmetic; what changed is that the mandatory trace makes it *auditable*. Expect that to surface as **more visible RETRY churn before fewer errors**.
